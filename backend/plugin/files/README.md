# 统一文件上传下载管理

提供统一文件上传下载能力，支持按类型存储、安全子目录、公开分享和文件归属校验
仅头像默认公开，其他类型默认私有；所有类型均可显式设置是否公开

## 插件类型

- 应用级插件

## 配置说明

在 `backend/.env` 中添加以下内容：

```env
FILE_STORAGE_ROOT='storage'
UPLOAD_READ_SIZE=1048576
FILE_UPLOAD_CHUNK_SIZE=4194304
FILE_UPLOAD_TTL_SECONDS=86400
FILE_UPLOAD_MAX_SESSIONS=10
FILE_UPLOAD_SIZE_LIMITS='{"file":1073741824,"avatar":5242880,"resource":2147483648,"document":536870912,"image":10485760,"audio":536870912,"video":1073741824}'
```

`FILE_UPLOAD_ALLOWED_TYPES` 为扩展名到 MIME 列表的 JSON 映射，完整默认值见
`backend/.env.example`。二进制文件使用 `filetype` 检查真实文件头，同时检查扩展名和
声明的 Content-Type；空值和 `application/octet-stream` 只允许省略声明，不能绕过真实类型检查。
UTF-8 文本补充检查编码和控制字符，支持 YAML、XML、HTML、CSS、JS、Python 和 Java 源码。
旧版 DOC/XLS/PPT 检查真实文件头；新版 Office 检查 ZIP 容器成员并拒绝宏。
默认不接受 SVG、可执行二进制文件和不能识别的二进制格式。HTML 和代码作为文件下载，
不提供可执行的静态展示地址；上传校验不代表代码或文档可以安全执行。

这些配置已在 `backend/core/conf.py` 声明并校验，单位均为字节。文件大小必须为正数且
不超过 JavaScript 安全整数上限 9007199254740991，数据库大小字段显式使用 BIGINT。
resource 默认最大 2 GiB，document 最大 512 MiB；未配置上限的类型不会放行。单片最大 4 MiB，
匹配部署 Nginx 的 5 MiB 请求限制，大文件通过多次分片请求上传。

## 使用方式

1. 确保插件已启用
2. 登录后上传文件，保存返回的文件 ID 和下载地址
3. 资源类型可指定安全的相对子目录，不允许绝对路径、上级目录、反斜杠或编码路径
4. 公开文件允许任何人匿名下载；普通下载接口访问私有文件须携带上传者的登录凭证，文件不存在和无权访问均返回 404。超级管理员通过独立管理接口下载其他用户文件
5. 文件统一保存在仓库根目录的 storage 中；存储配置支持绝对路径，相对路径按仓库根目录解析，不存在的目录自动创建
6. 所有头像均保存在 avatar 子目录；其他公开文件保存在 public/{类型}，私有文件保存在 {类型}，不再使用 private 子目录。公开头像和图片保留展示地址，私有头像同样只能由上传者下载；统一备份存储目录，反向代理将上传资源请求交给应用处理
7. 原有静态文件保留公开属性；敏感历史文件应重新上传为私有文件，再移除原公开副本

## 分片上传与断点恢复

前缀 `/api/v1/files`，所有上传操作必须登录：

1. `POST /upload/precheck`：提交 `filename`、`size`、完整 `sha256`、`content_type`，
   及可选 `upload_type`、`target_path`、`is_public`。返回 `upload_id`、`chunk_size`、
   `total_chunks`、已完成的 `uploaded_chunks`；若已经合并成功，直接返回 `file`。
2. `PUT /upload/{upload_id}/chunks/{index}`：请求体为原始字节，序号从 0 开始；
   `X-Chunk-SHA256` 为当前片 SHA-256。按服务端返回的片大小切分，最后一片允许较短。
3. `POST /upload/{upload_id}/merge`：验证所有分片、完整 SHA-256、实际大小和 MIME 后入库。
   相同会话重复合并返回原记录；会话和数据库提交受跨进程文件锁保护，冲突返回 409。
4. `DELETE /upload/{upload_id}`：取消会话并释放临时分片，不删除已入库文件。

相同用户和相同元数据重新预检即可恢复上传；不同用户不能访问彼此会话。
每用户最多 10 个未完成会话，默认空闲 24 小时过期；成功分片延长有效期。
临时文件在存储根目录 `.chunks` 下，预检及现有定时清理任务负责删除过期会话。
多进程和多实例必须共享支持文件锁的存储目录。

## 定时清理

任务名称：`backend.app.task.tasks.cleanup.tasks.delete_orphan_files`。
是否启用及执行周期以任务调度管理中的配置为准。

- 文件引用记录在 `sys_file_reference`，按文件、业务类型、业务 ID、字段唯一登记，不维护冗余引用计数。
- 新上传默认 `retention_policy=temporary`；文件中心直接上传显式使用 `persistent`，替换来源仍为临时文件。
- 头像和外部链接图标在业务保存事务内维护引用，替换、删除时解除旧引用，支持相对路径和文件下载 ID。
- 最后一条引用解除时设置 `unreferenced_at`；从该时刻起超过 `FILE_UPLOAD_TTL_SECONDS` 才允许回收。
  上传后取消编辑的临时文件同样适用；有引用、长期保留和软删除保留中的文件不会按临时文件回收。
- 建立引用、管理员删除及任务清理锁定同一文件记录；文件删除失败保留记录供下次重试。
- 文件删除失败时保留数据库记录并写入警告，下次执行重试。
- 物理文件已不存在时删除失效记录；路径无效时保留记录并报警，便于排查配置或迁移问题。
- 其他业务需在保存事务内调用 `reference_service.sync`，不能仅写 URL 而不登记引用。
- 过期上传分片由带锁的会话清理处理，正在上传和合并的会话会被跳过。
- 每周任务扫描超过 `FILE_UPLOAD_TTL_SECONDS` 的无记录磁盘文件，仅报告路径并保留。
- 独立年度任务 `backend.app.task.tasks.cleanup.tasks.delete_untracked_storage` 删除超过该保护期的无记录文件，
  从子目录向上清理空目录（不限制目录创建或修改时间），保留正常及软删除记录对应的文件、新文件及 `.chunks`。
  文件保护期默认 86400 秒（24 小时），防止删除尚未完成入库的上传文件；年度执行周期与保护期是两个独立条件。
  任务结果分别返回已删除文件、空目录、失败项、数据库记录对应的保留文件和保护期内的保留文件数量。
  不跟随符号链接或 Windows 目录联接；存在无法解析的记录时中止。
  默认每年 1 月 1 日 04:00（后端配置时区），任务调度页可调整；重启 Worker 和 Beat 后注册。
- 存储根目录不存在时终止任务，防止目录未挂载时批量删除数据库记录。

任务返回已清理记录数、过期会话数、失败文件数和保留的无记录文件数。

### 已有数据库升级

停用 API 和 Worker 的旧进程后，在后端根目录执行：

```sh
uv run python -m backend.plugin.files.migrate_references
```

脚本幂等增加字段和引用表，补齐当前头像、外部链接图标引用；首次升级时将已识别的业务文件纳入临时回收。
其他历史文件默认长期保留，避免把未知用途图片误删。历史已替换的普通图片无法可靠推断用途，
需管理员在文件中心确认后删除。迁移不删除物理文件，执行后重启 API 和 Celery Worker。
新建数据库通过模型建表自动包含这些结构。引用表有外键，卸载时先删除引用表。

前端 `uploadFileApi` 按块计算 SHA-256，自动重试临时失败并跳过已上传分片，支持
`AbortSignal` 和 `onProgress`。原单请求 `/upload` 保留兼容，受同样校验限制；
旧 `/api/v1/sys/files/upload` 仅保留注释函数，不再注册。

## 大文件下载

`GET` / `HEAD /api/v1/files/download/{file_id}` 支持 `Accept-Ranges: bytes`、
`Range`、`If-Range`、`ETag` 和 `Last-Modified`。有效范围返回 206 与 `Content-Range`；
超出文件范围返回 416；`If-Range` 不匹配时返回完整文件 200。所有请求先校验下载权限。
响应逐块读盘，反向代理关闭文件接口的响应缓冲与 gzip。

小文件可使用 `downloadFileApi` 获取 Blob；大文件使用 `downloadFileToDiskApi`，
传入 File System Access API 的文件句柄，按 4 MiB Range 写盘。中断后再次传入同一目标，
匹配 ETag 和本地文件状态后继续。该磁盘接口要求浏览器支持 File System Access API；
其它客户端下载接口同样可使用标准 HTTP Range 续传。

## 管理员文件中心

前端入口：系统管理 → 文件中心（`/admin/files`）。沿用系统管理权限，仅超级管理员可见；
后台管理接口同时验证 `is_superuser` 和 `is_staff`。普通上传、下载接口保留原有权限。

管理接口前缀为 `/api/v1/files/manage`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | 空路径 | 分页列表，支持 `page`、`size`、`name`、`upload_type`、`is_public`、`user_id`、`username` |
| GET | `/browse` | 通过 `path` 浏览当前目录；`recursive=true` 搜索所有子目录文件；返回文件相对路径 |
| GET | `/resource-folders` | 根据 `is_public` 返回已有资源相对目录，供上传选择；包含父目录 |
| GET | `/{file_id}` | 文件详情、上传者用户名及 ID、物理文件是否存在、是否为所属用户当前头像 |
| PUT | `/{file_id}/content` | 传入 `source_file_id`，用当前管理员上传的文件替换目标内容，保留目标 ID 和访问地址 |
| GET / HEAD | `/{file_id}/download` | 管理员下载公开或私有文件，支持 Range |
| DELETE | `/{file_id}` | 永久删除存储文件及数据库记录 |
| POST | `/batch-delete` | 接收 `ids`（1～200 个），返回 `deleted` 和逐项 `failed` |
| PATCH | `/{file_id}/visibility` | 接收 `is_public`，迁移存储位置并更新访问地址 |

分页接口支持 `sort_by`、`sort_order=asc/desc`，在分页前排序；上传者和可见性也可排序。
前端填写查询条件后跨所有目录搜索，并显示 `storage_path`。
可见性修改会改变直接访问地址；当前使用中的所属用户头像会同步更新用户资料和缓存。
文件迁移与数据库提交无法共同原子完成，修改后数据库提交失败时需核查路径与记录。

页面与用户、部门管理共用查询表单、VXE 表格和工具栏。支持目录和面包屑导航、
用户名查询、刷新、详情、分片上传、下载、替换和删除。列表仅包含未软删除的数据库记录，
不展示无记录磁盘文件或未完成上传分片。雪花文件 ID 和用户 ID 以字符串返回，避免浏览器丢失精度。
大文件下载沿用按块写盘与断点恢复，浏览器不支持文件保存 API 时仅允许不超过 100 MiB 的 Blob 下载。

目录按记录的实际存储路径生成，仅列出含有效记录的目录，不支持新建或移动空目录。
上传选择资源类型时，可选择或输入 `target_path`，最终目录为 `resource/{target_path}/YYYY/MM/DD`，
公开资源增加 `public/` 前缀；禁止绝对路径及路径穿越。替换先上传私有来源文件，不能以头像记录作为来源，
需要同扩展名并再次通过目标类型、大小及文件内容验证。目标的 ID、原名称、地址、
可见性和上传者不变；成功后消费来源文件及记录。替换失败时已上传来源保留，可手动管理。
替换采用同存储卷原子覆盖；文件系统与数据库无法共同原子提交，
若覆盖后数据库提交失败，需要核查目标大小及来源缺失记录。已有浏览器缓存可能需刷新后显示新内容。

删除前弹出不可恢复确认；使用中的所属用户头像禁止删除，路径存在重复记录时拒绝删除。
物理文件缺失时允许移除失效记录；存储根目录不可用或删除失败时保留记录。
普通业务引用没有统一登记机制，不能自动判断是否被其他页面使用，删除前应核实。
磁盘删除与数据库事务不能原子提交，若文件删除后数据库提交失败，会残留缺失文件记录，
可在恢复数据库后重新删除该记录。
